# P3C native CAD adapter

The host wraps **CAD Sketcher 0.32.1 and slvs 3.2**, the dependency combination that passed the P0 compatibility trial. Enable this pinned CAD Sketcher extension in host Blender before starting the Spatial Modeling host; reconnect clients if dependency availability changes. `welcome.capabilities.sketch` is true only when the extension is registered, its manifest version is 0.32.1 and native slvs 3.2 imports.

`sketch.apply(op, target_id, args)` runs through the existing Editor/Commands transaction path, inside session commit and the normal one-step native Undo wrapper. It does not start a second history or flush. The six typed sketch operations and existing scene sketch schema are unchanged. The adapter serializes native points/lines/analytic circles, native geometric constraints, driving dimension values and solver status/DoF. Scene updates replace complete sketch records; generations, removals, peer snapshots and receipts use the host machinery. The whole-sketch UUID is the lease target. Native curve UUIDs and constraint UIDs survive Undo/Redo and save/reopen. Rectangle corners share real point entities; H/V constraints drive the solver. `fixed` anchors a native point with CAD Sketcher's fixed attribute and retains its constraint ID on the sketch object.

Edits solve against a staged native Curves datablock with copied constraint PropertyGroups. On rejection the original datablock, object metadata and scene dimension-driver values are restored; no Undo step is pushed. The error receipt reports `conflicting` while the scene remains at its last valid `free` or `fully_constrained` state. Solver calls that fail to instantiate a driving native constraint are refused. Unknown exceptions pass through existing unknown-outcome/reconciliation handling after local rollback. Native dimension storage and editable constraints are saved in the `.blend`; display geometry is derived from them.

The pinned dependency caches UUID/index lists by Python `id(Curves)`. RNA wrapper identity can be reused after staged datablock replacement or a later read, so retaining those caches can return IDs from another sketch. This caused false entity/solver refusals and warm snapshots with incorrect origin IDs that differed from a cold native reopen. The adapter calls the dependency's public `invalidate_curve_id_cache()` at transaction start, copied-data assignment, rollback, commit and each sketch-record read. Direct native UUID attribute comparison now guards a repeated real-depsgraph regression; no dependency upgrade or ID substitution is used.

The bounded adapter supports planar XY/XZ/YZ sketches through world origin; points/lines/circles; coincident point/point or point/line; horizontal/vertical one-line or two-point constraints; fixed points; line length, point/point distance or point/line distance; two-line angles in radians; and circle diameters. Wire lengths are meters, converted by the native scene unit scale. Limits are 512 native curve entities and 1024 native constraints per sketch; existing dimensions remain editable at either exact limit. Degenerate lines/rectangles are rejected. Library-linked, free-3D and multiuser sketch datablocks are refused for editing. Non-unit, reflected or sheared native sketch frames are refused both for editing and serialization, since the wire plane carries only rigid rotation/translation. A serialization failure sends an explicit error and closes welcomed clients, making their previous scene stale/disconnected. Commands and new handshakes cannot pass their required native read while the fault persists. After the host restores a supported frame, sync sends a full authoritative snapshot and reconnects receive fresh editable data. Other native entity/constraint kinds are omitted from this bounded wire description while solver status still accounts for them. Advanced CAD, solids and arbitrary imported dependency graphs remain outside this adapter.

## Reproduce native gates

Use a disposable Blender with isolated user config/scripts outside the repository. Do not enable or reinstall an extension into the personal profile from a `--factory-startup` probe: Blender's dependency reconciliation may remove that profile's extracted wheels. Test setup reads the installed extension source, extracts its exact pinned Windows CPython3.13 wheel into the disposable evidence folder, and registers that package only inside the disposable process. It never saves preferences.

```
blender --background --factory-startup --python tests/native-sketch/check_sketch.py -- --extension <installed-CAD_Sketcher> --output <disposable-output> --phase create
blender --background --factory-startup --python tests/native-sketch/check_sketch.py -- --extension <installed-CAD_Sketcher> --output <same-output> --phase reopen
blender --background --factory-startup --python tests/native-sketch/check_transactions.py -- --extension <installed-CAD_Sketcher> --output <transaction-output>
blender --background --factory-startup --python tests/native-sketch/check_transactions.py -- --extension <installed-CAD_Sketcher> --output <production-host-output> --production-host
blender --background --factory-startup --python-exit-code 1 --python tests/native-sketch/check_depsgraph_identity.py -- --extension <installed-CAD_Sketcher> --output <identity-output> --phase create --cycles 30
blender --background --factory-startup --python-exit-code 1 --python tests/native-sketch/check_depsgraph_identity.py -- --extension <installed-CAD_Sketcher> --output <identity-output> --phase reopen
```

The first process solves anchored 100x60mm to120x60mm, circle diameter20mm to30mm, angle45deg to60deg, DoF0 and inconsistent opposite-width refusal with unchanged record/revision. The second process reopens all sketches, compares every entity/constraint ID and value, then solves the rectangle to130x60mm. The transaction gate uses actual loopback sockets on an ephemeral port, real Commands/Editor/Sync, two editing peers, solver receipts and replay/deduplication, one-step native Undo/Redo, whole-sketch lease refusal, owner edit, global-history refusal, native Save and a fresh peer's editable snapshot. A failed post-Save trial leaves the record, document description and count of native Curves datablocks unchanged. Nonrigid-sketch and injected evaluated-mesh failures send errors and close all welcomed clients without accepting a new revision; invalid reconnects and cached snapshots are refused. Restoring valid native data produces a full authoritative snapshot and further native editing works. `--production-host` exercises actual `host.start`, `host._drain` and `host.stop`, changing only the Server constructor's port to an ephemeral loopback port so another active host remains untouched.

Machine evidence and failed runs stay under local `planning/overnight/cad`; disposable `.blend` files stay outside OneDrive. These software gates do not establish physical VR authoring, actual second-PC behavior, strict arbitrary-host-Python write prevention or full P3C acceptance. Integrate behind cumulative P3B, run combined native/Unity checks and retain the hardware gates.
