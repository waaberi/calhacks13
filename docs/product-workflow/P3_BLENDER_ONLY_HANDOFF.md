## Strict-authority prototype: measured limit and required decision

The prototype reuses production command/Client paths. Native RNA location, an actual unwrapped modifier operator, direct child deletion, real scripted native Undo, native transform operator execution, and Outliner rename/collection-data changes in the mirror do not alter a new authoritative snapshot or its revision. The private worker independently confirms the 10 mm move and native CAD edits. Valid commands still use permission, revision/generation checks, receipts and native history; stale generations and solver conflicts refuse. Both processes exit cleanly; sources/dependencies remain unchanged. This tests local operations, not manual GUI clicks, headset gestures, hostile same-user OS access or WAN.

**The current mirror is not a full native editable CAD document.** Its sketch object is Blender `CURVE` display geometry without native `sketch_constraints`; it cannot run CAD Sketcher's full constraint UI. Ordinary native transform/edit/modifier/script/Outliner changes also have no automatic typed translation back to authority. Their local success does not mean a shared native edit happened. The prototype's native panel exposes only its explicitly mapped +10 mm action; direct shapes and dimensions use the existing typed transaction path. This panel is diagnostic-only and is not registered in the production application.

The required human architecture/scope decision is whether to authorize a substantially expanded private-authority adapter that maps the promised native UI/tool set (including modal, topology, constraint and persistence semantics), or revise the strict/full-tool requirement. Production remains the cooperative native authority until that decision. Do not advertise this narrow prototype as full Blender UI coverage or mark #87/RC16 passed. OS/process/filesystem isolation is also not implemented by this prototype.

Explicit unsupported prototype routes: unrestricted native mesh editing, modifiers, arbitrary scripts, Outliner mutations, generic modal tools, generic native CAD constraint UI, unmapped native actions, real controller/GUI delivery, second-PC/WAN and hostile OS access. Production direct drawing also continues to report unsupported native Continuous Draw, Auto Constraints and Live Project Snaps rather than silently ignoring them; disable these through Blender for the currently supported point bridge. Native 3D sketches/unsupported planes/options are reported per sketch while unrelated objects keep syncing.
