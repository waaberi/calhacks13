# Controller pointing and explicit object selection

The original selection repair was based on the exact tested main fbee0e1256ee56f77fb35eb70eb9ba65351710e5 build (final P2 plus voice, without P2.5). The current combined build also includes the wearer-requested menu and popup changes described below.

Aim either controller's visible ray at an actual 3D model object. When Voice transcription is enabled in Settings, its status identifies the pointed object. Right-hand pointing takes priority when both rays hit different objects; the left hand is used when the right ray has no eligible object. There is no headset-gaze fallback. Mesh hits use the current displayed controller aim and rendered mesh colliders, with nearer menu/screen/plane hits taking precedence.

Press and release that controller's front trigger to select the pointed object. Press and release it again on the SAME selected object to deselect it. Selection does not begin a grip, move an object or change native Blender selection/geometry. The wearer-requested menu cleanup removes the redundant **Select object** button; **Clear selection** remains available. Hover is cyan and explicit selection is yellow. Selection-title popups default OFF and can be enabled separately in Settings; the passive voice status also defaults OFF. Selection stays latched when the ray moves away and after a voice command, until toggled off, cleared, replaced, deleted or a document/session change.

Say a targeted command through the left menu push-to-talk button, for example **rotate it forty five degrees around x**. VoiceCore receives the selected UUID, so looking or pointing elsewhere does not replace an explicit selection. If a remembered command was only missing its target, selecting can complete that pending command, following the existing VoiceSession behavior. Cancel the pending command first if the intent is only to select.

An explicit spoken name overrides selection: `rotate cube` targets the object named Cube even if Cube.001 is selected. Use `it` or `this` for the selected object. A plain cube has the same appearance after90degree axis rotations;45degrees gives a visible orientation change. In the first repair's live trial, three rotations were actually applied (Z90, X90, Z90), native revision1 advanced to5 with a later Add, and Cube's native quaternion changed from identity to [0,-.707107,0,-.707107]. This is actual native/log evidence, not a wearer visual pass or blanket voice acceptance.

Grips retain accepted workspace/individual-part movement, stick alignment and two-hand behavior. While a grip owns a target, a trigger keeps its existing alignment action and does not select. A trigger on a menu or screen cannot select a model behind it. Tracking/focus loss clears transient pointing and requires a fresh input edge; explicit identity survives ordinary focus loss, while pending voice commands/delete confirmations are cancelled. Disconnection, new document epoch, deletion or hidden/non-current object invalidate selection. Host authority and native command validation stay unchanged.
